# 취약점 증적 양식

학생가이드 9.2의 **12개 항목**을 그대로 옮긴 템플릿.
취약점 하나당 아래 표를 한 벌씩 복사해서 채우면 됩니다.

개선 순서는 고정이다:
`취약 설정 → 점검 → Before 증적 → 코드 수정 → Plan·Apply → After 재점검 → 기능 확인`

---

## 템플릿 (복사해서 사용합니다)

### VULN-000 : (제목)

| # | 항목 | 내용 |
|---:|---|---|
| 1 | 자산명 / 자산 ID | |
| 2 | 점검 항목 · 기준 ID | KISA _____ / Security Hub _____ |
| 3 | 현재 설정 | |
| 4 | 점검 명령 · 화면 경로 | |
| 5 | 원본 점검 결과 | <details><summary>출력</summary><pre>(붙여넣기)</pre></details> |
| 6 | 취약 여부 / 위험도 | □취약 □양호 · P0/P1/P2/P3 |
| 7 | 판정 근거와 영향 | |
| 8 | 개선 방법 · 담당자 | |
| 9 | Terraform·설정 변경 | 파일:라인 / Git Commit |
| 10 | Plan·Apply 결과 | `+n ~n -n` / 스크린샷 |
| 11 | 동일 조건 재점검 | 4번과 **같은 명령**으로 다시 |
| 12 | 정상 기능 · 롤백 확인 | 차단 성공 + 기능 성공 **둘 다** |

> 11번은 4번과 같은 명령이어야 합니다. 다른 방법으로 확인하면 증적이 되지 않습니다.
> 12번은 "막혔다"만으로는 통과가 아닙니다. 필요한 통신은 성공해야 합니다.

## 작성 예시 — VULN-001 : 대시보드 5000 포트 노출 여부 점검

| # | 항목 | 내용 |
|---:|---|---|
| 1 | 자산명 / ID | dashboard EC2 / `i-________` |
| 2 | 기준 | 가이드 6.2 "0.0.0.0/0 : 5000 앱 서버 우회 접근" |
| 3 | 현재 설정 | dashboard SG 인바운드 TCP 5000 ← `var.vpc_cidr` (VPC 내부 전용) |
| 4 | 점검 명령 | `aws ec2 describe-security-group-rules --filters Name=group-id,Values=sg-____` |
| 5 | 원본 결과 | 소스가 VPC CIDR. 인터넷 경로 없음 |
| 6 | 판정 | **양호** |
| 7 | 근거·영향 | 퍼블릭 IP가 없는 private_app 서브넷에 있고 SG 소스도 VPC 내부입니다 |
| 8 | 개선 방법 | 해당 없음 |
| 9 | 코드 변경 | 없음 |
| 10 | Plan·Apply | 해당 없음 |
| 11 | 재점검 | 같은 명령으로 재확인 |
| 12 | 기능 확인 | `aws ssm start-session --document-name AWS-StartPortForwardingSession` 로 접속 성공 |

> 양호 판정도 증적입니다. "점검했고 문제없었다"를 같은 양식으로 남기면 됩니다.

## 이 프로젝트에서 소재가 되는 항목

이미 처리됐거나(✅) 개선 단계용으로 남겨둔(🔜) 것들.

| 소재 | 상태 | 비고 |
|---|---|---|
| ALB 0.0.0.0/0 개방 | 🔜 소재 | VULN-002 |
| 필수 태그(Owner) 누락 | ✅ 처리 | VULN-004 |
| `.gitignore` tfplan·ppk 누락 | ✅ 처리 | VULN-003 |
| SSH 22 인바운드 | ✅ 원래부터 없음 | Session Manager 전용 — 발표 강점 |
| DVWA 웹 취약점 (SQLi/XSS) | 🔜 | WAF on/off 비교로 Before/After |
| MySQL root 원격 접속 | 🔜 | user-data 확인 필요 |
| 컨테이너 이미지 취약점 | 🔜 | Trivy — Terraform 범위 밖 |
| 로컬 state 사용 중 | ⚠️ `backend.hcl.example` 준비됨 | bootstrap apply 는 직접 실행해야 함 |
| IMDSv2 / EBS 암호화 / Secrets Manager | ✅ 이미 적용 | "처음부터 지킨 것"으로 발표 |

**의도적으로 남긴 것**: 위 🔜 항목을 전부 미리 고쳐버리면 Before 증적을 만들 수 없습니다.
가이드 10일 일정의 6~7일차(점검) 전까지는 그대로 두는 편이 낫습니다.

## VULN-002 : ALB가 인터넷 전체에 개방

| # | 항목 | 내용 |
|---:|---|---|
| 1 | 자산명 / ID | ALB SG / `sg-________` |
| 2 | 기준 | 가이드 6.2 · 11장 "이유 없는 직접 노출 금지" |
| 3 | 현재 설정 | `alb_http` · `alb_https` 인바운드 ← `0.0.0.0/0` |
| 4 | 점검 명령 | `aws ec2 describe-security-group-rules --filters Name=group-id,Values=sg-____` |
| 5 | 원본 결과 | ⬜ Before 출력 |
| 6 | 판정 | 취약 · P1 (뒷단이 DVWA라 위험도가 올라갑니다) |
| 7 | 근거·영향 | 의도적으로 취약한 앱이 인터넷에 노출됩니다. 실습 목적이라도 제3자가 접근 가능한 상태는 피해야 합니다 |
| 8 | 개선 방법 | `modules/network/sg.tf` 의 `cidr_ipv4` 를 `var.admin_cidr` 로 |
| 9 | 코드 변경 | `sg.tf:24`, `sg.tf:33` |
| 10 | Plan·Apply | ⬜ `~ 2 changed` 예상 |
| 11 | 재점검 | ⬜ 같은 명령 → `0.0.0.0/0` 없음 |
| 12 | 기능 확인 | ⬜ 본인 IP에서 `curl $(terraform output -raw web_url)` 성공 |

## 증적 파일 보관 위치

```
docs/evidence/
├─ before_YYYYMMDD/      점검 원본 출력
├─ after_YYYYMMDD/       재점검 출력
├─ verify_YYYYMMDD.json  demo/verify-controls.sh --json 결과
└─ plan_YYYYMMDD.txt     terraform plan 출력
```

`demo/verify-controls.sh` 가 차단·기능 검증을 한 번에 돌리고 `--json` 으로 증적을 남깁니다.
