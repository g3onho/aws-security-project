## 1. 자원 목록과 시간당 추정 비용

기본값 기준: `enable_vpc_endpoints = true`, ALB·NAT·공격자 off

인스턴스 타입은 변수 3개로 나뉘어 있습니다. **4대가 전부 t3.micro 가 아닙니다.**

| 변수 | 기본값 | 적용 대상 |
|---|---|---|
| `instance_type` | `t3.micro` | web_dvwa, dashboard, attacker |
| `docker_host_instance_type` | `t3.small` | docker_host |
| `db_instance_type` | `t3.small` | db |

| 자원 | 수량 | 단가(추정) | 시간당 | 비고 |
|---|---:|---|---:|---|
| EC2 t3.micro (web_dvwa, dashboard) | 2 | $0.0144/h | $0.0288 | |
| EC2 t3.small (docker_host, db) | 2 | $0.0288/h | $0.0576 | micro 의 2배 단가 |
| EBS gp3 root (30+20+20+20 = 90GB) | 90GB | $0.0912/GB·월 | $0.0112 | docker_host 만 30GB |
| 퍼블릭 IPv4 (퍼블릭 서브넷 인스턴스) | 1 | $0.005/h | $0.0050 | web_dvwa 1대뿐. 2024년부터 유료 |
| **VPC 인터페이스 엔드포인트** (ssm/ssmmessages/ec2messages/**monitoring**) | 4 | $0.011/h | $0.0440 | **기본 on** |
| **소계 — 항상 켜짐** | | | **$0.1466** | **약 하루 $3.52** |
| 공격자 EC2 (`enable_attacker_instance`) | 0~1 | $0.0144/h | $0.0144 | **기본 off** |
| NAT Gateway (`enable_nat_gateway`) | 0~1 | $0.059/h + $0.062/GB | $0.0590 | **기본 off** |
| ALB (`enable_alb`) | 0~1 | $0.0225/h + LCU | $0.0225 | **기본 off** |
| WAF WebACL (`enable_waf`) | 0~1 | $5/월 + 룰 $1/월×2 | $0.0096 | ALB 켤 때만 |
| ECR 저장소 | 1 | $0.10/GB·월 | 소액 | 수명주기 정책으로 정리 |
| VPC 엔드포인트 `logs` (선택) | 0~1 | $0.011/h | $0.0110 | **미적용.** 붙이면 Nginx·MySQL 로그 수집 |

> VPC 엔드포인트가 기본 on 인 이유는 NAT 대신 Session Manager 경로를 여는 것이라서입니다.
> NAT($0.059/h)보다 엔드포인트 4개($0.044/h)가 쌉니다.
>
> **`monitoring` 은 v12 에서 추가했습니다.** 없으면 CloudWatch Agent 가 정상 기동해도
> `PutMetricData` 가 나갈 경로가 없어 **메모리 지표가 영원히 올라오지 않습니다**(SEC-10).
> 에이전트 상태는 `running` 으로 보여서 원인을 찾기 어렵습니다. 다만 **일반 인터넷 접근이 필요하면
> NAT가 별도로 필요**합니다. 둘 다 켜면 비용이 겹칩니다.

## 2-1. 1차 실행 실측 (2026-09-21)

추정치만 있으면 감이 안 잡혀서, 실제로 약 4시간 가동하며 관측한 값을 남긴다.

| 항목 | 실측 | 비고 |
|---|---|---|
| EC2 가동 | 4대 (micro 2 · small 2) | 공격자 off |
| CloudTrail S3 객체 | 252개 | 약 4시간 누적. 대부분 수 KB |
| Security Hub finding | 100건 | **97건이 `INFORMATIONAL`** — 평가할 리소스 없음 |
| Inspector finding | 88건 | linux-image-aws 커널 CVE 대부분 |
| GuardDuty finding | 4건 | 루트 계정 사용 탐지 |
| CloudWatch Logs 수집량 | **0** | `logs` 엔드포인트가 없어 전송 자체가 안 됨 |

**읽을 거리 두 가지.**

**Security Hub 과금은 finding 수가 아니라 점검 실행 수를 따른다.** 표준을 켜면 이 계정에
없는 서비스(Redshift·SageMaker·WorkSpaces 등)까지 전부 평가한다. 실제로 100건 중 97건이
"평가할 리소스 없음"이었다. 비용은 적지만 **화면이 빈 결과로 뒤덮여 진짜 탐지를 가린다.**
조회 상한 100건을 그 노이즈가 다 먹어서 Inspector CVE 88건이 아예 보이지 않았다.

**CloudWatch Logs 비용이 $0 인 것은 좋은 신호가 아니다.** 수집이 되지 않고 있다는 뜻이다.
`logs` 엔드포인트를 붙이면 Flow Logs·Nginx·MySQL 이 실제로 쌓이기 시작하면서
수집 GB당 요금이 생긴다. 위 표의 "$2 ~ $10 변동" 구간이 그때 현실화된다.

## 4. 표준 실행 절차

```bash
terraform init
terraform fmt
terraform validate
terraform plan -out=tfplan   # ← 팀에 공유하고 비용 재확인
terraform apply tfplan       # ← 2차 승인 후에만
```

`-auto-approve` 는 쓰지 않습니다. plan에 `-/+ replace` 가 보이면 무엇이 지워지는지 먼저 확인하면 됩니다.

## 5. 종료 절차

```bash
terraform plan -destroy   # 삭제 대상 검토
terraform destroy         # 강사 확인 + 증적 백업 완료 후
```

**CloudTrail 버킷은 destroy 전에 비워야 합니다.** `force_destroy = false`(cloudtrail.tf:52)라
버전이 남아 있으면 `BucketNotEmpty` 409 로 destroy 가 중단됩니다. 실제로 1차 종료 때 걸렸습니다.

```bash
B=soar-sec-dev-cloudtrail-<계정ID>
aws s3api delete-objects --bucket $B --delete   "$(aws s3api list-object-versions --bucket $B      --query '{Objects: Versions[].{Key:Key,VersionId:VersionId}}' --output json)"
```

증적으로 보관할 거면 지우기 전에 `aws s3 sync` 로 내려받습니다.

destroy 후 콘솔에서 직접 확인해 주세요 — S3 버킷(객체 남으면 삭제 실패),
CloudWatch Log Group, KMS 키(삭제 대기), Elastic IP, Inspector/GuardDuty 활성화 상태.
