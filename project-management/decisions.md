## 1. 상태와 기록 방식

- **확정**: 사용자 또는 지정된 책임자가 선택을 명확히 승인했다. 영향받는 문서와 계약을 갱신한다.
- **미결정**: 근거와 가능한 선택지는 정리했지만, 승인된 방향이 없다. 기능 목표나 기존 코드만으로 추정하여 확정하지 않는다.
- **대체됨**: 이후 결정이 과거 선택 또는 지시를 명시적으로 대체했다. 역사 기록은 남기되 현재 기준으로 사용하지 않는다.
- **검증된 현행 사실**: 코드나 자료에서 읽기 전용으로 관찰한 사실이다. 그 자체는 설계 승인이나 실환경 검증을 뜻하지 않는다.

각 항목은 결정 ID, 상태, 결정 내용 또는 질문, 근거, 영향 문서·기능, 재검토를 유발하는 조건을 가진다. 사용자 확인 날짜가 별도로 기록되지 않은 결정에는 임의 날짜를 넣지 않는다. 설계 선택을 바꾸면 기존 항목을 덮어쓰지 말고 새 결정과 대체 관계를 기록한다.

구현이 설계와 다르면 아래 중 하나로 분류하고 추적표에 근거를 연결한다.

- **구현 수정 대상**: 확정 설계가 유효하고 코드가 이를 충족하지 않는다.
- **설계 갱신 대상**: 요구사항·제약 변경이 확정되어 기존 설계를 바꿔야 한다.
- **임시 예외**: 승인된 이유·범위·종료 조건을 기록하고 제한된 기간 동안만 벗어난다.

미결정 상태는 임시 예외가 아니다. 미결정 설계에 맞추기 위해 기존 구현을 고치거나 운영 환경에 적용하지 않는다.

## 2. 확정 결정

| ID | 상태 | 결정 | 근거와 영향 |
|---|---|---|---|
| DEC-001 | 대체됨 | 모든 신규 가이드 문서를 루트 아래 `project/` 폴더에 두고, `project.md`와 `agents.md`도 그 안에 두려던 초기 배치 지시다. | 후속 지시 DEC-010으로 대체됐다. 이 행은 당시 결정의 기록이며 현행 파일 경로로 사용하지 않는다. |
| DEC-002 | 확정 | dashboard 접근 경로의 기준은 Terraform에 선언된 방식이다: 조건부 ALB의 HTTP 8080 경로를 대시보드 5000으로 전달하고, SSM Session Manager 포트 포워딩으로 5000에 접속한다. SSH 22를 대시보드 접근 수단으로 추가하지 않는다. | 사용자가 Terraform 명시 경로 채택을 선택했다. 이 결정은 어떤 경로가 실제 배포된다는 뜻이 아니며, Terraform 변수·리소스 조건에 따른다. ALB 진입 CIDR, 애플리케이션 인증과 운영 배포 조건은 별도 미결정이다. |
| DEC-003 | 확정 | dashboard의 운영 작업·승인·감사 자료 저장 목표는 DynamoDB다. 현재 SQLite 사용은 목표에 대한 구현 편차이며 구현 수정 대상으로 기록한다. | 사용자가 DynamoDB 설계를 유지하고 SQLite 편차를 수정 대상으로 지정했다. 관련 dashboard 계약, Terraform 저장소 책임과 tracking을 함께 갱신한다. SQLite의 로컬 개발 지원 범위와 마이그레이션 절차는 미결정이다. |
| DEC-004 | 확정 | DVWA는 Nginx–Flask–MySQL 업무 서비스, dashboard, 허니팟과 구분된 별도 웹 공격 시험 대상으로 둔다. | 사용자가 DVWA 추천안을 채택했다. 허가된 ZAP/SQLi 검증과 WAF 반응은 DVWA 대상 주소와 실제 WAF 연결을 확인해 평가한다. 결과가 다른 웹 서비스의 보안성을 증명한다고 확대 해석하지 않는다. |
| DEC-005 | 확정 | MySQL 인증 실패 검증 경로는 CloudWatch로 두고, SSH 공격 시도 검증 경로는 GuardDuty로 분리한다. | 사용자가 두 검증 경로를 각각 지정했다. Config의 SSH 포트 구성 finding과 GuardDuty 행위 finding은 다른 증거다. SSH GuardDuty 관측 경로 선택은 SSH의 자동 차단이나 SOAR 연결을 승인하지 않는다. |
| DEC-006 | 확정 | Nginx 보안 강화는 수동 변경·검증 흐름으로 진행한다. 보안 헤더와 HTTPS/TLS 강화는 권장 기준으로 다루되, 실제 HTTPS 완료 판정은 리스너·인증서·마운트·TLS 종료 지점이 연결되고 검증될 때까지 보류한다. | 사용자가 권장 Nginx 보안 설정을 선택했다. 현재 Terraform·Compose와 SSM 문서에는 443 연결·인증서 마운트의 간극이 있으므로 설정 파일 생성만으로 TLS 적용을 주장하지 않는다. 애플리케이션 호환성 검토와 TLS 배치 세부사항은 별도 결정이 필요하다. |
| DEC-007 | 확정 | 자동 조치 경로에 새 사용자 확인 단계를 추가하지 않는다. 자동 조치의 적용 범위·정책·예외·복구를 확장하는 설계는 후속 과제로 남긴다. | 사용자가 “확인 단계를 두지 않은 채” 후속 설계 과제로 두도록 선택했다. 이는 실환경 실행을 허가하거나 기존 게이트의 충분성을 인증한 것이 아니다. 기존 코드의 화이트리스트·전역 토글·SG 태그 등 조건은 경로별로 추적하며 사람 승인 여부와 별도 축으로 표현한다. |
| DEC-008 | 확정 | AI 허니팟은 프로젝트 목표 범위에 포함하되, 기술, 모델, 배치, 세션 분석, 저장소와 자동 차단 정책은 확정하지 않는다. | 사용자는 목표 범위는 포함하고 세부 기술·차단은 미결정으로 지정했다. 이전 프롬프트에 있던 Beelzebub, OpenAI, Bedrock, 즉시 NACL 차단과 새 DynamoDB 테이블은 현행 기준에서 제외하며 구현된 기능처럼 표현하지 않는다. |
| DEC-009 | 확정 | 커밋 제목은 버전만 사용한다. 주요 변경은 vN, 사소한 수정은 vN.M 형식이며 제목에 설명·접두사·괄호·날짜를 붙이지 않는다. | 사용자가 확정한 형식. 상세 변경 내용과 커밋 SHA는 변경 기록 및 tracking에서 연결한다. |
| DEC-010 | 대체됨 | `project.md`와 `agents.md`를 저장소 최상위에 두고, 기능별 설계와 공통 관리 문서를 각 최상위 폴더에 배치한다. AI 편집기 설정 파일은 자동 인식 위치인 저장소 최상위와 `.github/`에 둔다. 별도의 `project/` 래퍼 폴더는 두지 않는다. | 기존 경로 배치 결정이다. README를 프로젝트 전체 진입점으로 삼는 후속 결정 DEC-011로 파일명 기준이 대체됐다. 나머지 디렉터리 배치 기준은 유지한다. |
| DEC-011 | 확정 | 전체 프로젝트 개요와 4계층 아키텍처의 정본은 저장소 루트 `README.md`로 둔다. `agents.md`와 자동 인식 AI 지침은 작업 시작 때 루트 README를 먼저 읽도록 한다. 기능별 설계 문서와 공통 관리 문서는 기존 최상위 폴더 구조를 유지한다. | 사용자가 GitHub 저장소 첫 화면에서 전체 설계 진입점을 바로 확인할 수 있도록 파일명 변경을 선택했다. README가 진입점과 상위 설계 정본을 겸하며, 기존 `project.md` 참조·내부 링크를 새 파일명에 맞춘다. |
| DEC-012 | 확정 | 관제 대시보드에 '공격·대응 실습' 페이지를 추가한다. 1차 범위는 관측·구조(조회 전용)이며 실제 공격·부하·SSM 실행은 구현하지 않는다. 실행 유형은 웹 보안 검사(ZAP), 보안 시나리오(SEC-01~10), 부하 시험(CPU·메모리 통합)으로 둔다. CPU·메모리 사용률 상승 자체를 침해로 표기하지 않는다. | 사용자가 1차 관측·구조 범위와 선택 UI(실행 없음)를 선택했다. 화면은 실행 유형·대상·시나리오 선택과 실행 가능 여부 표시까지 동작하고 '시작'은 비활성이다. 실제 실행·중단·재검증과 실행 접수·타임라인·증거 계약은 후속(2·3차) 과제이며 실행 공급자·권한은 OPEN-015·016·017로 미결정이다. 신규 조회 API(/api/drills*)와 dashboard-design·tracking·openapi를 함께 갱신한다. |

## 3. 확인된 편차와 처리 구분

다음은 문서 작성 시 확인한 코드·자료의 정적 사실이며, 운영 중 적용이나 검증이 완료되었다는 뜻은 아니다.

| ID | 사실 및 근거 | 설계 기준과 차이 | 분류·처리 |
|---|---|---|---|
| GAP-001 | dashboard 코드에 SQLite 기반 users/events/jobs/requests/audit 저장소가 있고, dashboard 설계는 DynamoDB를 목표로 한다. | 저장 책임이 목표 기준과 다르다. | DEC-003에 따라 **구현 수정 대상**. DynamoDB 계약·전환·복구는 tracking에서 경로와 검증 상태를 추적한다. 로컬 개발용 SQLite 허용 범위는 구현 수정 기준을 바꾸지 않고 별도 결정한다. |
| GAP-002 | Terraform에서 ALB 접근은 선택적이며 dashboard_ingress_cidr 기본값이 전역 범위로 읽혔다. 대시보드 리스너는 HTTP다. | 사용자는 Terraform에 명시된 접근 경로를 채택했으나, 운영 허용 범위와 인증 정책은 승인하지 않았다. | **미결정 운영 정책**. Terraform 기본값만으로 운영 공개 범위를 승인된 것으로 보지 않는다. 배포 시 CIDR·인증·세션 보호·전달 경로를 재검토한다. |
| GAP-003 | 확인된 EventBridge의 GuardDuty→ASR 필터는 IAM 자격 증명 유형에 한정되고, SSH 관련 자동 조치 연결은 확인되지 않았다. | GuardDuty는 SSH 공격 검증 경로로 채택됐지만 자동 조치 경로 선택은 아니다. | 현재는 **자동 연결 부재를 결함으로 단정하지 않는다**. SSH finding의 실탐지와 수집은 SEC-06B로 검증한다. 향후 SSH 자동 대응을 승인하면 새 설계·요구 ID와 안전 기준을 결정한다. |
| GAP-004 | 보안 그룹 조치 코드에서 화이트리스트, 전역 토글, 대상 SG 태그를 검사하고 IAM 키 조치에서는 태그 조건이 확인되지 않았다. | 자동 경로별 게이트가 서로 다르다. | **현행 사실 및 후속 정책 검토**. 이를 균일한 3중 안전장치라고 설명하지 않는다. DEC-007은 확인 단계 추가를 허용하지 않았으며, 장기 정책을 확정하지 않았다. |
| GAP-005 | Nginx 강화 SSM 문서에는 TLS·헤더 설정이 있으나 Compose는 80 포트만 연결하고 인증서 마운트 및 443 종단이 맞지 않는 부분이 있다. 해당 SSM 문서가 SOAR 핸들러와 연결된 근거도 확인되지 않았다. | 권장 강화 설정은 수동 목표지만 종단 간 HTTPS 실행 조건은 미완성이다. | **구현 수정 대상과 미결정 설계 분리**. 헤더 적용은 수동 검증; TLS 종단·인증서·443 노출 방식이 정해지기 전에는 HTTPS 완료로 판정하지 않는다. |
| GAP-006 | MySQL CloudWatch metric filter와 alarm에 기본값 및 Terraform 변수가 있으나, 기본 숫자가 사용자 승인된 보안 정책인 근거는 없다. | 코드 기본값과 목표 임계값은 동일하지 않다. | **미결정 정책**. 문서에는 현행 기본값을 근거 자료로만 기록하며 운영 임계값으로 확정하지 않는다. |
| GAP-007 | 기존 시나리오 보조 스크립트는 직접 Lambda 호출, 연결 실패만으로 PASS 처리할 수 있는 확인, cleanup 제한이 관찰되었다. | 스크립트 출력만으로 실제 탐지·조치·정리를 입증할 수 없다. | **검증 증거의 제한**. tracking에는 정적 검토와 실행 검증을 구별한다. 이 문서 작업 중 스크립트나 AWS 실행은 수행하지 않았다. |

## 5. 미결정 질문 처리 절차

미결정 질문을 개발에 영향 주는 변경으로 처리하기 전에 다음을 따른다.

1. 질문 ID, 확인된 사실, 상충 근거, 결정이 필요한 역할과 선택지를 기록한다.
2. 선택마다 보안 영향, 구현·운영 영향, 복구 및 검증 영향을 설명한다.
3. 답변이 설계에 영향을 주면 해당 사용자의 명확한 선택을 결정 상태로 남긴다. 기술적 표현만의 수정은 새 정책 승인으로 해석하지 않는다.
4. 선택 후 README.md, 관련 기능 설계, 시나리오, glossary와 추적표를 갱신한다. 실제 코드 편차는 구현 수정 대상·설계 갱신 대상·승인된 임시 예외 중 하나로 분류한다.
5. 선택 전 수행한 독립 작업은 계속할 수 있지만 미결정 동작을 구현하거나 운영에 적용하지 않는다.

## 6. 구현·검증 기록과 변경 추적

이 문서는 “무엇을 선택했는가”를 기록한다. 코드가 실제로 무엇을 하는지, 어떤 경로가 선언·호출·연결되었는지, 테스트가 수행되었는지는 tracking.md에서 근거와 함께 기록한다. 문서에 적힌 결정이 실환경에 배포되었다고 추정하지 않는다.

다음 변경은 결정 기록을 검토한다.

| 변경 | 갱신할 기록 |
|---|---|
| 새 사용자 선택 또는 이전 선택 변경 | 새 DEC 항목, 이전 항목의 대체 상태, 영향 문서 |
| 확정 기준과 코드가 다름 | DEC의 분류·이유, tracking의 코드 경로·구현 상태·검증 상태 |
| 정책 수치 또는 재시도·보존·신선도 값 승인 | 근거, 소유자, 적용 범위, 검증 기준, 변경된 기능 문서 |
| 임시 예외 승인 | 예외 범위, 이유, 만료/종료 조건, 위험 소유자, 원복 검증 |
| 구현 상태나 검증 결과만 변경 | tracking만 갱신. 설계 결정 상태를 구현 완료로 바꾸지 않음 |

커밋 제목은 DEC-009 규칙만 사용한다. 해당 결정·구현·검증 상세는 변경 기록과 tracking에서 실제 커밋 SHA에 연결한다. 존재하지 않는 버전, 검증, 사용자 승인을 소급해서 작성하지 않는다.
