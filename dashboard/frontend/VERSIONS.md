# 대시보드 버전 정의

정의일: 2026-09-20

## v1.0 — 이전 구현 기준

현재 구현된 AWS Security Operations 프론트엔드 데모를 v1.0으로 정의한다. 실행 버전은 `VERSION` 파일에 기록한다.

- Flask에 연결 가능한 HTML·Tailwind CSS·JavaScript·Chart.js 구성.
- 차콜 배경과 민트 강조색, 지도 중심 관제 화면.
- 서울·도쿄·싱가포르·프랑크푸르트·버지니아의 5개 리전과 별도 글로벌/위치 미상 항목.
- 지도 마커, 지역 선택, 확대·축소 버튼, 지역 상세 패널.
- 통합 관제·보안 이벤트·취약점 점검·인프라 모니터링·대응 이력.
- 공통 필터, 시간 구간, 검색, CSV 내보내기.
- 데모 승인·취소·조치·재검증 성공/실패, Before/After 비교.
- 반응형 화면과 키보드 접근성, 감소된 모션 설정 지원.

검증 기록은 `VERIFICATION.md`를 참조한다. 버전 정의 자체는 새로운 기능 검증이나 코드 스냅샷 생성을 의미하지 않는다.

## v2.0 — 구현 완료

사용자가 제안한 아래 다섯 항목을 v2.0 범위로 정의하고 구현했다. 최종 색상은 사용자의 ‘기존 디자인 사용’ 지시에 따라 v1.0의 차콜·민트로 확정했다. 색상 샘플은 참고용으로 보존하며 실행 화면에는 적용하지 않는다. 현재 실행 버전은 v2.0이다.

### 3. 공격 시작 IP에서 대상까지 선 표시

공격 출발 IP의 지리 위치에서 대상 AWS 리전 또는 대상 자원 대표 위치까지 방향성 있는 선을 표시한다.

- 이벤트 데이터에 출발 IP, 출발 위치, 대상 리전/자원, 위치 출처를 구분해서 담는다.
- 출발 위치는 IP 문자열만으로 계산할 수 없으므로 별도의 위치 데이터가 필요하다. IP 지리 위치는 근사치이며 실제 공격자의 물리적 위치로 단정하지 않는다.
- 위치 정보가 없는 IP, 사설 IP, 좌표 없는 글로벌 이벤트는 지도로 임의 배치하지 않고 상세 정보에 위치 미상을 표시한다.
- 프론트엔드 데모에서는 모의 IP·좌표임을 명시한다. 실제 위치 조회 서비스 연결은 별도 범위다.
- 선택 이벤트 또는 현재 필터의 이벤트와 연결하고, 상세 정보에 출발 IP·목적지·탐지 시각·위험도를 표시한다.
- 선의 방향을 식별할 수 있게 한다. 곡선과 절제된 이동 효과는 구현 제안이며, 선이 많을 때는 선택 항목을 강조해 가독성을 유지한다.
- 선은 관측된 출발지와 대상의 관계를 나타내며, 실제 인터넷 라우팅 경로를 의미하지 않는다.

### 4. 지도 마우스 조작

- 확대한 지도 위에서 마우스를 누른 채 끌어 이동한다.
- 지도 위 스크롤 휠로 확대·축소한다.
- 포인터 주변을 중심으로 확대하며 최소·최대 배율과 이동 범위를 제한한다.
- 지도 밖에서는 기존 페이지 스크롤을 유지한다.
- 드래그를 마커 클릭으로 오인하지 않도록 구분한다.
- 기존 확대·축소·초기화 버튼과 키보드 조작을 유지한다.

### 5. 지구의 약한 입체감

사용자 요구는 지구를 약간 입체적으로 표현하는 것이다. 구현 방향으로는 지표의 완만한 곡률, 은은한 음영과 가장자리 깊이감을 제안한다. 정확한 표현 방식은 구현 시 시각 결과를 보며 조정한다.

- 지도·마커·공격 연결선에 일관된 투영을 적용해 어긋나지 않게 한다.
- 국가 경계, 가까운 리전 마커, 공격 흐름이 읽히는 수준의 입체감을 유지한다.
- 자동 회전은 요청 범위에 포함하지 않는다.
- 현재 지도 중심 배치와 상세 패널을 유지하고, 감소된 모션 설정과 작은 화면에서의 사용성을 보존한다.

## v2.1 — 구현 완료 (지도 회전/줌 개편 + 위협 행위국 데이터)

사용자가 요청한 네 항목을 v2.1 범위로 정의해 구현했고, 이후 사용자 피드백을 반영해 드래그 회전 방향을 수정하고 위협 행위국 데이터를 8개국으로 확장했다. 실행 버전은 2.1로 변경했다.

### 1. 리전 선택 시 자동 확대 강화

`chooseRegion()`이 리전을 선택하면 해당 리전의 경위도를 화면 중심(회전각)으로 맞추고 줌을 `REGION_ZOOM`(2.2×, 기본값 1.55×보다 확실히 확대된 값)까지 애니메이션으로 전환한다. `prefers-reduced-motion` 설정 시에는 애니메이션 없이 즉시 전환한다.

### 2. 공격 출발지 데이터 — 주요 사이버 위협국 8개국으로 교체·확장 (옵션 A)

기존 파리/뉴욕/시드니 고정 좌표(v2.0에서 추가된 파리·시드니 리전과 좌표가 겹쳐 "리전이 리전을 공격"하는 것처럼 보이던 문제)를 제거하고, 공개 위협 인텔리전스 자료(CISA, MITRE ATT&CK 등)를 참고해 구성한 국가 데이터(`threatActors`, `static/js/data.js`)로 교체했다. 최초 4개국(북한·중국·러시아·이란)에서 사용자 요청에 따라 베트남(APT32/OceanLotus)·파키스탄(APT36/Transparent Tribe)·인도(Patchwork/APT-C-09)·튀르키예(Sea Turtle)를 추가해 8개국으로 확장했다. `country` 필드는 지도·상세 패널 표기를 위해 영문 국가명(North Korea, China, Russia, Iran, Vietnam, Pakistan, India, Turkey)으로 통일했다. 각 항목은 대표 그룹(예시), 목적, 주요 타겟, 주요 전술을 담고 있으며, 이벤트 상세 다이얼로그의 "공격 출발지 → 대상" 섹션에 표시된다. 개별 이벤트에 대한 실제 귀속(attribution)이 아니라는 문구를 함께 표시한다. 8개국 좌표는 17개 리전 좌표와 겹치지 않음을 확인했다. 또한 `createEvents()`의 공격 출발지 선택을 리전 인덱스뿐 아니라 이벤트 인덱스로도 변화시키고, 각 지리 리전의 첫 두 슬롯을 서로 다른 국가의 공격으로 강제 배정해 "리전당 최소 2개국 이상"을 보장한다(`tests/v2.1-data-check.mjs`로 17개 리전 전체를 검증).

### 3. 기본 줌 배율 조정 — 지구본 테두리 숨김

투영을 정사영(orthographic)으로 바꾸면서 지구 테두리는 항상 화면 중심의 원(`globe-rim`)이 되도록 단순화했다. 기본 줌(`DEFAULT_ZOOM` 1.55×)에서 이 원의 반지름이 1000×460 뷰박스의 대각 코너까지의 거리보다 커지도록 계수를 맞춰, 기본 화면에서는 테두리가 보이지 않는다. `zoom-out` 버튼으로 최소 배율(1×)까지 축소하면 테두리가 다시 보일 수 있다(의도된 동작).

### 4. 드래그 회전형 지구본 + 최단 경로(대권) 공격선

`static/js/map.js`의 투영을 평면 "2.5D 개요도"에서 실제 회전 가능한 정사영 투영으로 전면 교체했다. 회전 상태는 `[lambda0, phi0]`(중심 경도·위도)로 관리한다. 드래그 방향은 처음에 "오른쪽으로 끌면 경도가 증가"하는 방식(카메라를 동쪽으로 돌리는 방식)으로 구현했으나, 실제로 조작해 보니 커서를 따라오지 않고 반대로 느껴진다는 피드백을 받아 표준적인 트랙볼(구체를 손으로 잡고 돌리는) 방식으로 수정했다 — 드래그를 시작한 지점의 표면이 커서를 그대로 따라오도록(오른쪽으로 끌면 화면 중심에 있던 지점이 오른쪽으로 이동하고, 왼쪽에 있던 새 지역이 중앙으로 들어옴) `lambda0`/`phi0`의 부호를 반전했다(`tests/v2.1-projection-check.mjs`로 방향을 검증). 국가·지구 테두리·경위선(graticule)은 회전할 때마다 `project()`로 다시 계산해 다시 그린다(고정 카메라 CSS 트랜스폼 방식은 더 이상 사용하지 않는다). 공격선은 두 좌표 사이의 대권(최단 구면 경로)을 40개 구간으로 나눠 보간하고, 중간 지점에서 살짝 떠오르도록 고도값을 준 뒤 정사영으로 투영해 입체적인 곡선으로 표현한다. 지구 뒷면으로 넘어가는 구간(국가 경계, 경위선, 공격선 모두 포함)은 앞면 기준으로만 그리는 단순화된 클리핑을 사용한다(진짜 구면 다각형 클리핑은 아니며, 지평선 부근에서 미세한 직선 이음새가 보일 수 있는 의도된 절충이다). 드래그·휠·방향키 조작은 매 프레임(`requestAnimationFrame`)마다 한 번씩만 다시 그려 성능을 관리한다.

### 유지 사항

기존 접근성(키보드 조작, `prefers-reduced-motion`), 5개 필터, 상세 패널, CSV 내보내기, 마커를 클릭으로 오인하지 않는 드래그 판별 로직은 v2.0과 동일하게 유지했다.

### 검증

`node --check`로 `map.js`/`data.js`/`app.js`/`store.js` 구문을 확인했고, `tests/v2.1-projection-check.mjs`(정사영 투영·트랙볼 드래그 방향·줌 상수 검증)와 `tests/v2.1-data-check.mjs`(8개국 threatActors 데이터, 좌표 비충돌, 리전당 최소 2개국 공격, 대권 공격선 렌더링 검증)를 새로 추가해 통과를 확인했다. 이번 작업 환경에서는 실제 브라우저로 화면을 직접 띄워 보는 검증(기존 `tests/browser-check.cjs`, `tests/v2-check.cjs`와 같은 Playwright 기반 화면 검증)은 수행하지 못했다 — 개발 환경의 로컬 서버와 실제 브라우저가 서로 다른 네트워크에 있어 접근할 수 없었다. `start-dashboard.cmd` 실행 후 팀 환경에서 화면을 직접 확인하고, 필요하면 기존 v2-check.cjs를 참고해 v2.1용 브라우저 검증 스크립트를 추가하는 것을 권장한다.

## v2.2 — 구현 완료 (기본 화면·국가 강조·리전 줌 보완)

사용자가 업로드한 참고 영상(IBM Private Cloud 대시보드 컨셉 영상)을 프레임 단위로 분석해 정확한 시각 효과를 확인한 뒤 세 항목을 v2.2 범위로 구현했다. 실행 버전은 2.2로 변경했다.

### 1. 전체 리전 선택 시 기본 화면

`chooseRegion()`은 v2.1부터 이미 리전 id가 `all`이거나 좌표가 없는 경우 `animateTo(DEFAULT_ROTATION, DEFAULT_ZOOM)`으로 돌아가도록 되어 있었다. v2.2에서는 이 동작을 그대로 "전체 리전 선택 시 돌아갈 기본 화면"으로 확정하고, 동시에 국가 강조 상태(`selectedCountryIndex`)도 함께 초기화되도록 `updateSelectedCountry()` 호출을 추가했다 — 전체 리전으로 되돌아가면 카메라뿐 아니라 국가 강조도 함께 해제된다.

### 2. 리전 선택 시 소속 국가 밝게 표시

업로드된 참고 영상을 ffmpeg로 프레임 추출하고 픽셀 색상을 분석한 결과, 마커 선택 시 해당 마커가 속한 국가의 폴리곤 전체가 RGB(38,38,38) 근방에서 RGB(57~59, ·, ·) 근방으로(채도·색조는 그대로, 명도만 약 1.5배) 밝아지고 다른 국가는 변하지 않는 효과임을 확인했다. 이를 그대로 재현하기 위해 `static/js/map.js`에 점-다각형(point-in-polygon) 판정 함수 `findCountryIndex(lon, lat, features)`를 새로 추가했다 — 짝수-홀수 규칙의 표준 ray-casting 방식이며 `MultiPolygon`과 다각형 내부의 구멍(hole)도 처리한다. `static/js/app.js`는 리전을 선택할 때마다 `updateSelectedCountry()`로 해당 리전 좌표가 속한 국가의 인덱스를 계산해 `renderCountries()`에서 그 국가에만 `country-selected` 클래스를 부여한다. `static/css/app.css`에는 기존 `#countries path` 채우기색(`#303d37` 계열)을 유지하면서 명도만 올린 `#4d6258`(대체 테마 `#515d58`) 강조색과 `.3s` 전환 효과를 추가해, 색조가 바뀌지 않고 밝기만 바뀌는 참고 영상의 효과를 그대로 구현했다.

**한 국가에 AWS 리전이 여러 개인 경우(사용자가 직접 판단을 위임한 부분)**: 리전별로 분기하지 않고, 국가 단위의 점-다각형 판정만 사용한다. 즉 미국(버지니아·오하이오·캘리포니아·오리건 4개 리전)이나 일본(도쿄·오사카 2개 리전) 중 어떤 리전을 선택하더라도 동일한 "미국"/"일본" 국가 전체가 밝아지며, 리전이 바뀌어도 국가가 같으면 강조 결과는 동일하다. 국가별로 별도 처리를 두지 않는 이 방식이 가장 일관되고 유지보수가 쉽다고 판단해 채택했다(`tests/v2.2-country-highlight-check.mjs`에서 4개 리전 전체가 동일한 인덱스로 귀결되는지 확인).

**싱가포르 데이터 한계 — 해결 완료**: `static/data/countries.geojson`(원본 177개 국가, 저해상도 Natural Earth 110m 계열)에는 싱가포르가 도시국가라는 이유로 처음부터 별도 폴리곤이 없었고, 싱가포르 좌표(103.82, 1.35)가 단순화된 말레이시아 폴리곤 내부에 들어가 있어 `ap-southeast-1`(싱가포르) 리전을 선택하면 실제로는 "말레이시아"가 밝아지는 문제가 있었다. `datasets/geo-countries`(OSM 기반, Natural Earth보다 고해상도) 공개 데이터셋에서 실제 싱가포르 경계(폴리곤, 약 40개 정점)를 가져와 `countries.geojson`의 **맨 앞(인덱스 0)**에 `ADMIN: "Singapore"`로 추가했다. `findCountryIndex`는 배열 순서대로 첫 번째로 일치하는 폴리곤을 반환하므로, 새로 추가한 정밀한 싱가포르 폴리곤이 뒤에 있는(기존) 말레이시아의 부정확한 폴리곤보다 먼저 판정되어 이제 정확히 "Singapore"로 강조된다. 말레이시아 본토 좌표(예: 쿠알라룸푸르)는 이 변경의 영향을 받지 않고 여전히 "Malaysia"로 정확히 판정됨을 별도로 검증했다(`tests/v2.2-country-highlight-check.mjs`). 전체 국가 수는 177개에서 178개로 늘었고, 파일 크기 증가는 약 1.3KB로 미미하다.

### 3. 리전 선택 시 확대 배율 상향

`REGION_ZOOM`을 2.2×에서 2.6×로 올렸다(`ZOOM_MAX`는 3.2×로 유지되어 범위 안에 있음). 기본 줌(1.55×)과 최대 줌(3.2×) 사이에서 리전 선택 시 이전보다 눈에 띄게 더 확대되도록 조정했다.

### 유지 사항

v2.1의 드래그 회전, 대권 공격선, 8개국 위협 행위국 데이터, 접근성·필터·CSV 내보내기 동작은 그대로 유지했다.

### 검증

`node --check`로 `map.js`/`data.js`/`app.js`/`store.js` 구문을 확인했고, 새로 추가한 `tests/v2.2-country-highlight-check.mjs`로 17개 AWS 리전 전부와 4개 위협 행위국 좌표가 `countries.geojson`에서 올바른 국가로 귀결되는지, 미국·일본처럼 리전이 여러 개인 국가가 항상 같은 인덱스로 귀결되는지, 싱가포르가 정확히 자신의 폴리곤으로 판정되고 말레이시아 본토 판정에는 영향이 없는지까지 모두 검증했다. 기존 `tests/v2.1-projection-check.mjs`, `tests/v2.1-data-check.mjs`도 재실행해 회귀가 없음을 확인했다. v2.1과 마찬가지로 이번 세션에서도 로컬 서버와 실제 브라우저가 다른 네트워크에 있어 실제 화면을 띄워보는 브라우저 검증은 수행하지 못했다 — 팀 환경에서 `start-dashboard.cmd` 실행 후 직접 화면(특히 국가 강조 밝기)을 확인하는 것을 권장한다.

## v2.2.1 — 후속 수정 (싱가포르 재확인 + 지도 색상 대비 전면 개선)

사용자가 "싱가포르 수정이 안 되어 있다"고 재차 알려주어 실제 브라우저(Claude in Chrome)로 로컬 대시보드(`http://127.0.0.1:5000`)에 직접 접속해 검증했고, 동시에 "전체적인 사이트 색상 조정으로 지도가 잘 보였으면 좋겠다"는 요청을 반영해 지도 색상 대비를 전면 개선했다.

### 1. 싱가포르 재확인 결과 — 서버 데이터는 정상, 실제 원인은 낮은 색상 대비

`countries.geojson`을 직접 fetch해 확인한 결과 싱가포르는 배열 0번 인덱스에 정상적으로 들어 있었고, 리전을 "싱가포르"로 선택하면 `country-selected` 클래스가 실제로 싱가포르 폴리곤(면적 기준 177개국 중 119번째로 작음 — 말레이시아 전체가 아님)에 정확히 붙는 것을 DOM에서 직접 확인했다. 즉 로직·데이터 자체는 이전 수정대로 정상 동작하고 있었다. 다만 아래 2번 문제(지도 전체의 육지/바다 색상 대비가 극도로 낮음, 대비비 약 1.16:1)때문에 화면에서는 어떤 국가가 강조되어도 거의 안 보였던 것으로 파악된다 — 특히 싱가포르는 실제 지도상 크기가 매우 작아 이 낮은 대비의 영향을 가장 크게 받았다. 전체 리전 목록이 있는 `select` 캐시 버스팅 파라미터도 없었던 점을 감안해, `app.js`의 `countries.geojson` fetch에도 버전 쿼리(`?v=2.2.1`)를 추가해 향후 이런 종류의 브라우저 캐시 의심 상황 자체를 원천 차단했다.

### 2. 지도 색상 대비 전면 개선

`static/css/app.css`를 분석한 결과, 파일 뒷부분에 앞쪽 `:root`/`#countries path` 정의를 소리 없이 덮어쓰는 중복 스타일 블록이 있었고(미디어 쿼리 등 조건 없이 항상 적용됨), 실제로 화면에 렌더링되던 육지 색상(`#343c39`)이 지구본 바다 그라디언트 중심색(`#25332e`)과 명도가 거의 같아 **WCAG 대비비 약 1.16:1**(거의 구분 불가능한 수준)이었던 것이 근본 원인이었다. 이 낮은 대비 때문에 국가 강조 효과(v2.2에서 구현)도 눈에 잘 띄지 않았다.

다음과 같이 색상을 재조정했다(동일한 초록빛 계열 색조는 유지하고 명도 단계만 명확히 분리):

| 요소 | 이전 | 변경 후 | 비고 |
|---|---|---|---|
| 육지 채우기 | `#343c39` | `#518574` | 바다 중심색 대비 1.16:1 → 3.11:1 |
| 육지 테두리 | `#1d2521` | `#172b24` | 육지 대비 3.5:1 확보 |
| 선택 국가 강조 | `#515d58` | `#a2cdbf` + 테두리 `#cbe6dc` + 은은한 글로우 | 육지 대비 2.43:1, 바다 대비 7.55:1 |
| 지구본 테두리(globe-rim) | `#436451` | `#53937b` | 지구 실루엣이 더 선명해짐 |
| 위경도 그리드(graticule) | `#52745e` (불투명도 .21) | `#588970` (불투명도 .28) | 미세하게 강화, 여전히 은은함 |
| 지도 캔버스 배경 | `#151d1b`/`#171c1b`(중복 정의) | `#101614`로 통일 | 지구본보다 더 어둡게 해 심도감 부여 |

실제로 렌더링되는(뒤쪽에서 덮어쓰는) 블록과 더 이상 렌더링되지 않는 앞쪽 블록 모두에 동일한 새 색상을 반영해, 추후 누군가 중복 블록을 정리하더라도 이전의 낮은 대비 색상으로 되돌아가지 않도록 했다. 국가 선택 강조에는 기존 마커(`.marker .core`)와 동일한 `drop-shadow` 글로우 패턴을 적용해 사이트 전반의 "빛나는 강조" 시각 언어와 통일감을 유지했다.

### 검증 — 이번에는 실제 브라우저로 직접 확인

이전 v2.1/v2.2에서는 개발 환경 제약으로 실제 브라우저 화면 검증을 하지 못했지만, 이번에는 Claude in Chrome으로 실제 브라우저에서 `http://127.0.0.1:5000`에 접속해 다음을 직접 확인했다:
- 전체 리전 개요 화면과 개별 리전 확대 화면 모두에서 대륙 윤곽이 뚜렷하게 구분됨(스크린샷으로 전후 비교).
- 싱가포르 리전 선택 시 `#countries path.country-selected`의 `fill`이 `rgb(162,205,191)`(`#a2cdbf`)로, 다른 일반 국가는 `rgb(81,133,116)`(`#518574`)로 정확히 렌더링됨을 DOM에서 직접 측정.
- 강조된 폴리곤의 bounding-box 면적(19.91)이 여전히 싱가포르 크기(177개국 중 119번째로 작음)와 일치해 말레이시아 전체가 아닌 싱가포르만 강조됨을 재확인.

`node --check`와 기존 `tests/v2.1-projection-check.mjs`, `tests/v2.1-data-check.mjs`, `tests/v2.2-country-highlight-check.mjs`도 모두 재실행해 회귀가 없음을 확인했다. 실행 버전은 2.2.1로 변경했다.

## v2.2.2 — 후속 수정 (전체 리전 기본 화면 재설계 + 공격선 돌출 버그 수정)

사용자가 스크린샷으로 "공격선 화살표가 지구본 밖으로 삐져나온다"는 문제를 제보하면서, 동시에 "전체 리전 선택 시 기본값을 1.0배율로 한국 중심으로 재설계해달라"고 요청했다. 실제 브라우저로 재현·검증하며 두 가지를 모두 처리했다. 추가로 "글로벌 / 위치 미상" 항목이 무엇인지도 설명했다(코드 변경 없음, 3번 참고).

### 1. 공격선 화살표가 지구본 밖으로 튀어나오는 문제 — 실제 버그로 확인, 수정 완료

사용자 제보를 Claude in Chrome으로 실제 로컬 대시보드(`http://127.0.0.1:5000`)에서 재현했다. "전체 리전" + "7일" 필터로 51개 공격선을 렌더링한 뒤 각 선의 마지막 좌표(화살표가 붙는 지점)와 지구본 테두리 반지름을 비교한 결과, 여러 공격선의 끝점이 실제 지구본 원(당시 R≈589px) 밖으로 **최대 47px(약 8%)** 벗어나 있음을 좌표 단위로 직접 확인했다.

**원인**: 공격선은 3D 입체감을 위해 중간 지점에서 살짝 "떠오르는"(고도 리프트, 최대 8%) 형태로 그려지는데(v2.1), 화면에 그릴지 말지를 정하는 가시성 판정(`vis>0`, 즉 구체 앞면인지)은 리프트 적용 **전** 원래 표면 좌표만 보고 있었다. 지평선 부근(거의 옆에서 보이는 지점)에서는 "표면상으로는 앞면(방금 보임)"이지만 리프트 때문에 실제로 찍히는 화면 좌표는 지구본 원 밖으로 밀려나는 경우가 생겼고, 이 지점이 마침 경로의 마지막 점(화살표 위치)이면 지구본 밖에 화살표만 동동 떠 있는 것처럼 보였다. `static/js/map.js`의 파일 상단 주석에 "지평선 부근 미세한 직선 이음새"라고 적어둔 v2.1 당시의 알려진 트레이드오프보다 실제로는 훨씬 눈에 띄는 결과였다.

**수정**: `connectionMarkup()`에서 각 점을 그릴지 판정할 때 기존의 `vis>0` 조건에 `해당 점이 실제 화면상 지구본 반지름(R = BASE_R × zoom) 이내인지` 조건을 추가했다(`static/js/map.js`). 즉 구체 앞면이라도 리프트 때문에 화면상 지구본 원을 벗어나면 그 지점부터 선을 끊는다. 수정 후 같은 "전체 리전 + 7일" 시나리오(51개 공격선)의 모든 점을 다시 측정한 결과 지구본 원을 벗어나는 점이 **0개**(최댓값 -0.02px, 즉 전부 원 안쪽)임을 확인했다. `tests/v2.1-projection-check.mjs`에 이 리프트-오버슈트를 재현하는 검증(8번 항목)을 추가해 회귀를 막는다.

### 2. 전체 리전 선택 시 기본 화면 — 1.0배율 · 서울 정중앙으로 재설계

`static/js/map.js`의 `DEFAULT_ZOOM`을 1.55 → **1.0**으로, `DEFAULT_ROTATION`을 `[127,15]`(동아시아 대략 중심)에서 **`[126.978, 37.566]`**(서울/ap-northeast-2 리전 좌표와 정확히 일치)로 변경했다. 이 두 상수는 "전체 리전" 선택, 페이지 최초 진입, ⌖(지도 초기화) 버튼에서 모두 공유되므로 세 곳 모두 동일하게 적용된다.

이 변경은 v2.1에서 "지구의 끝이 보이지 않게 배율 조정"했던 결정을 사용자의 명시적 요청으로 **되돌리는** 것이다 — 1.0배율(`ZOOM_MIN`과 동일)에서는 지구본 테두리가 뷰포트 안에 보인다. 의도적으로 되돌린 것이며 버그가 아니라는 점을 분명히 기록해 둔다. `tests/v2.1-projection-check.mjs`의 관련 검증도 "테두리를 숨긴다"가 아니라 "테두리가 보이는 것이 의도"로 뒤집어 갱신했다.

### 3. "글로벌 / 위치 미상"이란? (변경 없음, 설명)

리전 목록의 `글로벌 / 위치 미상` 항목(`static/js/data.js`의 `regions` 배열, `id:'global'`)은 지리적 리전에 속하지 않는 두 종류의 탐지를 묶어 보여주는 가상 항목이다: (1) IAM 역할 신뢰 정책처럼 특정 AWS 리전이 아니라 계정 전체에 걸친 **글로벌 스코프의 탐지**(`IAM-01` 시나리오), (2) 공격 출발 IP의 지리 좌표를 확인할 수 없는 **위치 미상 이벤트**(사설 IP 등). 리전 패널 하단의 "글로벌 / 위치 미상 N건 ↗" 버튼을 누르면 이 항목으로 필터링된다.

### 검증

`node --check`로 전체 JS 구문을 확인했고, 기존 3개 테스트 스위트(`v2.1-projection-check.mjs`, `v2.1-data-check.mjs`, `v2.2-country-highlight-check.mjs`)를 모두 재실행해 통과를 확인했다. 이번에는 Claude in Chrome으로 실제 로컬 서버(`http://127.0.0.1:5000`)에 접속해 (1) 수정 전 51개 공격선 중 다수가 지구본 원 밖으로 최대 47px 벗어나 있음을 좌표로 직접 측정하고, (2) 수정 후 같은 51개 공격선 전부가 지구본 원 안쪽(오버슈트 0)임을 재측정했으며, (3) "전체 리전" 선택 시 1.0배율·서울 중심 화면이 실제로 렌더링됨을 스크린샷으로, (4) 싱가포르 국가 강조가 새 기본값 아래서도 여전히 정상 동작함을 회귀 확인했다. 실행 버전은 2.2.2로 변경했다.
